## Implementation details and client responsibilities

- Gemini uses asynchronous HTTP against the official API; OpenAI/Claude use their async SDKs with automatic retries disabled. Provider/model IDs from the initial specification remain configurable and may no longer be available on a particular provider account.
- Rate limiting uses native async Redis operations and bounded in-memory fallback, rather than synchronous SlowAPI Redis access. Configurable fixed windows default to 20 auth, 30 AI/quiz, and 120 general API requests per minute. SSE concurrency is separately limited to two per user in normal Redis operation.
- Grounding checks validate citation IDs conservatively, not semantic truth. `confidence` and `total_tokens` are nullable when the upstream/heuristic cannot supply defensible measurements.
- Source reduction is a deterministic selected-section window, not a full token-aware document summarization pipeline. Quiz generation currently requires at least 20 whitespace-delimited source words; no retry is submitted automatically for malformed model output.
- Browser extension work (PDF extraction, private tab storage, refresh-only retries, preserving drafts, staging full-resync cache, conflict resolution UI, optional hint display) belongs to the client and is specified in the API/ADRs; it is not implemented by this backend repository.
- Bind requests require Redis coordination; during its outage new rebinding returns `503 SERVICE_DEGRADED`. Existing/new streams otherwise follow the documented degraded concurrency/cancellation policy.
- `PERSISTENCE_FAILED` retains text in the current client UI for copying; no retry-save API exists in the MVP.
- Local `.env` is ignored and contains generated development secrets; no credentials are committed. Host service ports are configurable in Docker Compose. No production deployment or default admin account is created automatically.
